# MAFAULDA public-dataset pretraining — provenance, counts, results

Built for `plans/2026-09-12-sensors-strategies-datasets.md` Decision 6, by
`ml/fl/mafaulda_download.py` -> `mafaulda_ingest.py` -> `dataset.py` ->
`pretrain.py`. Survey/selection rationale: `ml/data/DATASETS.md` (C0).
Downloads live under `ml/data/mafaulda/` (git-ignored; only this file and
`DATASETS.md` are tracked).

## Provenance

Both files downloaded to their exact verified sizes (resume-safe downloader,
no retries needed) and passed `zipfile.testzip()` with no corrupt members.
`normal.zip` contains 49 CSVs (`normal/<freq>.csv`), `imbalance.zip` contains
333 CSVs under mass-labelled folders (`imbalance/6g/...`, `imbalance/10g/...`,
etc.) — both counts match `DATASETS.md`'s expected file counts exactly.

**Licence caveat** (from `DATASETS.md`): MAFAULDA has no explicit
machine-readable licence text on the official page or elsewhere found in the
C0 survey. It is a long-standing (since ~2007) free, no-paywall, no-login
academic dataset with a contact email for questions. Treat this as "free to
use, cite the associated papers" rather than a confirmed permissive OSI
licence — flag to the founder if strict licence text is a hard requirement
for the shipped product.

## Column order (confirmed, not assumed)

Each CSV is 250,000 rows x 8 columns, comma-separated, no header (50 kHz x 5
s). Verified against the first `normal/*.csv` file's per-column min/max/std:
column 0 has by far the widest, most bimodal swing (min -1.13 V / max 5.11 V
on a ~0 V baseline — consistent with a Hall-sensor tachometer pulse train);
columns 1-3 and 4-6 show the graduated x>y>z variance pattern of two
triaxial accelerometer mounts. This matches the brief's stated order exactly:

`tachometer(0), underhang accel x/y/z(1-3), overhang accel x/y/z(4-6), microphone(7)`

**RPM finding:** the tachometer's dominant-FFT-bin frequency runs
~1.97x the filename-encoded nominal frequency for most files (consistent with
2 tachometer pulses per revolution), with occasional harmonic-detection
outliers on a handful of files (2nd/3rd harmonic dominating instead). Used
only as a relative proxy to group files into rpm bins ("virtual machines"),
not as a physically-exact RPM claim — this doesn't affect the bin-based
cross-validation, which only needs a monotonic speed ordering.

## Counts

rpm bins (708-7260, from the tachometer dominant-frequency estimate above),
plus 333 synthetic Airflow Obstruction samples (class 2 has **no public data**
— see `DATASETS.md`'s finding that no surveyed source gives per-file
clogging/airflow labels within the 3 GB budget; these are generated by

## Leave-one-bin-out cross-validation: random vs. contrastive init (`base` head)

Contrastive pretraining: SimCLR-style, 200 steps, Adam 1e-3, on all 382 real
clips (two views per clip: Gaussian noise 0.1, 10% band dropout, mixup 0.2;
projection 32-d; NT-Xent temperature 0.1; loss 4.83 -> 2.18 over training).
Both arms then fine-tune with the same SGD+weight-decay (1e-4) recipe, batch
8, lr 0.05, up to 30 epochs, early stopping (patience 5) on a 20% held-out
split of each fold's training folds.

| fold | held-out rpm bin | random acc | random macroF1 | contrastive acc | contrastive macroF1 |
|---|---|---|---|---|---|
| 0 | 708-1800   | 0.678 | 0.537 | 0.579 | 0.497 |
| 1 | 1800-2892  | 0.902 | 0.784 | 0.902 | 0.738 |
| 2 | 2892-3984  | 0.906 | 0.784 | 0.899 | 0.757 |
| 3 | 3984-5076  | 0.945 | 0.757 | 0.932 | 0.634 |
| 4 | 5076-6168  | 0.974 | 0.816 | 0.974 | 0.816 |
| 5 | 6168-7260  | 0.959 | 0.658 | 0.959 | 0.901 |
| **mean** | | **0.8940** | **0.7226** | **0.8740** | **0.7238** |

Confusion matrices (rows=true, cols=pred, classes 0=Healthy/1=Imbalance/2=Airflow), summed over all 6 folds:

```
random:               contrastive:
[ 15  22  12]         [ 15  23  11]
[ 47 272  14]         [ 56 253  24]
[  0   0 333]         [  0   0 333]
```

**Winning init: random** (mean accuracy 0.8940 vs. 0.8740 for contrastive;
no tie). Class 2 is separated perfectly in both arms (it's synthetic and
linearly-in-a-band separable by construction); most confusion is Healthy
vs. Imbalance at the lowest-rpm bin (fold 0), where Healthy has only 13
clips and the class imbalance (13 vs 102) is worst.

## Final heads (trained on ALL 715 samples, random init, 80/20 early-stopped)

| variant | layers | weights | init | epochs run | val acc | `.tflite` size | `pretrained_<id>.bin` |
|---|---|---|---|---|---|---|---|
| base  | [260,64,3]    | 16899 | random | 29 | 0.9583 | 85,096 B | 67,596 B |
| small | [260,32,3]    | 8451  | random | 30 | 0.9514 | 50,280 B | 33,804 B |
| deep  | [260,64,32,3] | 18883 | random | 23 | 0.9583 | 99,992 B | 75,532 B |

`small`'s first layer is 260->32; the contrastive projection was pretrained
at width 64 (to match `base`/`deep`'s first layer) and can't be copied into a
32-wide layer, so `small` always trains from the seed-7 random init
regardless of which arm wins the CV — moot here since random won outright.
All three `.tflite` files' `get_signature_list()` still report exactly
`infer`, `train`, `get_weights`, `set_weights`; `get_weights()` on each
returns these trained weights, not the seed-7 init.

## Deviations from the contract

- `ml/logmel_reference.py` does `import librosa` at module level; this venv
  deliberately has no librosa (brief: "no librosa"). `mafaulda_ingest.py`
  uses `ml/fl/logmel_np.py` instead, a pure numpy/scipy reimplementation of
  the same STFT (n_fft 2048, hop 1024, periodic Hann, center=False) + HTK
  mel-filterbank (norm=None) + log + mean/std math — same numbers, no
  librosa dependency. `logmel_reference.py` itself is untouched.
- `app/.../ml/signal/{Detrend,HannWindow}.kt` (referenced by
  `ImuVibrationIndex.kt`) do not exist yet in this repo (owned by a different
  workstream). The accel-index mirror in `mafaulda_ingest.py` uses the
  standard definitions instead (least-squares linear detrend via
  `scipy.signal.detrend`, symmetric Hann via `numpy.hanning`) since the exact
  Kotlin source couldn't be read to confirm periodic-vs-symmetric windowing.
